# Inline grid editing audit (2026-10-21)

Inline editing (cell context menu → *Insert Row* / *Edit in grid*, `packages/MainUI/components/Table`) was compared
with the form view (`components/Form/FormView`). Both save through the same endpoint
(`POST /api/datasource/<entity>?_operationType=add|update`, `DataSourceServlet` → `JsonToDataConverter`) and build
the body with the same `buildSavePayload`; the differences come from what the grid puts in that body, how it
initializes the row and how it reads the reply.

## Fixed

Each one was reproduced against a local Etendo and is pinned by
`playwright-tests/e2e/smoke/04_Masterdata/ADMeInlineGridEditingTest.spec.ts` (numeric parsing by
`components/Table/__tests__/CellEditors.test.tsx`).

| Bug | Cause | Fix |
|---|---|---|
| One Enter on a new row inserted the record twice | Enter saved; `setRowSaving` disabled the inputs, the focused one blurred and the row's `onBlur` saved again | `handleSaveRow` keeps a per-row in-flight set (`savingRowIdsRef`) |
| A business error (unique key, trigger) was POSTed 3 times; a network error after commit could insert twice | `saveRecordWithRetry` retried every `_general` error | Saves are sent once (`saveRecord`); the retry code was removed |
| A rejected new row disappeared with no message, the window stayed dirty | `rollbackOptimisticUpdate` dropped the new row while it stayed in `editingRows` | A failed new row stays on screen, still editable |
| Fast typing (barcode scanner) saved a truncated value (`"PW"` for `"PW fast typing"`) | `useThrottledCallback` ran the trailing call with the 2nd call's arguments and ignored the rest | Cell changes apply immediately (`useStableCallback` only keeps the identity) |
| Clicking a dropdown's search box on a new row saved the row | The row's `onBlur` used a DOM `contains` check; dropdowns and dialogs render in a portal | Focus moving into or out of a `menu`/`listbox`/`dialog` no longer counts as leaving the row |
| After a second save the grid showed the previous values; the next edit got a false stale-object 409 | The post-save `datasource.get` was answered from the 30 s response cache | The entity (and parent entity) cache is cleared first, as the form does |
| `"1,5"` became 15 in Spanish | `NumericCellEditor` stripped every comma | The user's language decimal separator is used, same rule as `NumericSelector` |
| Conversion errors (`status: -4`, `response.errors` map) showed "Unknown server error" | Only `response.error.message` was read | The map is joined into the message, as `useFormAction` does |
| The first save with validation errors showed no dialog | The dialog read the row snapshot taken before validating | It reads the row after validation |

### Parity with the form view (second pass)

| Gap | Fix |
|---|---|
| Extension-module `em_*` values were not copied into the standard column on save | The grid saves with `buildFormPayload`, the form's builder |
| New child rows dropped the parent link (keyed by `inputName`) | Row initialization uses `buildFormInitialState`, extracted from `useFormInitialState`: parent data by `hqlName`, booleans, static defaults, `@Column@` references, `$_entries`, identifiers by `hqlName` |
| No session reset before a root-tab NEW, FIC `sessionAttributes` never merged | `useInlineEditInitialization` runs `clearRecordContextFromSession` and `mergeSessionAttributes` like `useFormInitialization` |
| EDIT sent no record values to the FIC and the FIC values overwrote the row (datetimes shifted) | The record's `inp*` values are sent and the record's own values win the merge, as in the form |
| A save right after a callout field change missed the callout's values | `handleSaveRow` waits for `globalCalloutManager.waitForIdle()` and re-reads the row; row writes now update `editingRowsRef` immediately, so reads after a write are never stale |
| Callout payload: unsanitized changed value, temporary id sent as key, `em_*` fields ran the module callout, out-fields only for the product | Changed value through `buildPayloadByInputName`; no key value for new rows; standard `CHANGED_COLUMN` via `deriveStandardInputName`; generic `applyOutFields` and `buildGridVisibleProperties`, now shared in `utils/callouts/calloutPayload.ts` (the product fallback only fills inputs the out-fields did not set) |
| Two rows' callouts for the same field replaced each other in the global queue | Grid callouts are keyed by row and field |
| Display logic was not evaluated | Hidden cells are not editable and are not required; save-time validation follows `useFormValidation` (displayed, not read-only, display logic; non-updatable fields required on new rows; values read by `hqlName`) |
| The optimistic snapshot hid newer base rows | Rows are released from it after a save or cancel, and it is discarded when no row is edited |
| Escape cancelled the first edited row of every grid, twice in text editors | Only an unhandled Escape inside the grid cancels its edit |
| The keyboard manager saved with first-render closures | It calls the current save/cancel through refs |
| Tab moved alphabetically | Tab follows the on-screen order |
| No parent refresh after saving a child row; CSRF / AccessTableNoView errors were not handled | `triggerParentRefreshes` on child tabs; `logoutOnSessionSaveError`, extracted from `useFormAction` |
| TableDir options cached by field and organization only | Cached by the request itself, which carries the row and parent context |
| `crypto.randomUUID` fails on plain HTTP | New row ids use `generateLocalRecordId` |
| `accountingDate: new Date()` was sent as `{}` (shared with the form) | Sent as a `yyyy-MM-dd` string; still needed by tabs without the field (Copy from Orders, Landed Cost) |
| `windowId` was empty on inline saves | `buildQueryString` falls back to `tab.window` |

E2E coverage (`ADMeInlineGridEditingTest`) adds Escape in a dropdown and a line created inline in a child tab
(Payment Term → Lines, checks the parent link). The other second-pass fixes are covered by unit tests or were
verified by reading: no smoke spec covers a window where an `em_*` field stands in for a hidden standard column,
and the callout wait, display logic and session paths need windows the inline spec does not open yet.

## Known remaining differences

- The grid evaluates display and read-only logic with the session and the row values; the form also uses the
  parent record, auxiliary inputs and window preferences.
- Shared with the form: the FIC's `jsExecuteCode`, `dynamicCols` and `overwrittenAuxiliaryInputs`, and callout
  `sessionAttributes`, are ignored; a callout replaced in the global queue never resolves its promise.
- The server ignores `oldValues`; the only concurrency check is `data.updated`, to the second.
- `createEmptyRowData` keys its placeholder values by column label; they are never read and the save drops them.
