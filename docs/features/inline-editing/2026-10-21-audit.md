# Inline grid editing audit (2026-10-21)

Inline editing (cell context menu → *Insert Row* / *Edit in grid*, `packages/MainUI/components/Table`) was compared
with the form view (`components/Form/FormView`). Both save through the same endpoint
(`POST /api/datasource/<entity>?_operationType=add|update`, `DataSourceServlet` → `JsonToDataConverter`) and build
the body with the same `buildSavePayload`; the differences come from what the grid puts in that body, how it
initializes the row and how it reads the reply.

## Fixed

Each one was reproduced against a local Etendo and is pinned by
`playwright-tests/e2e/smoke/04_Masterdata/ADMeInlineGridEditingTest.spec.ts` (numeric parsing by
`components/Table/__tests__/CellEditors.test.tsx`).

| Bug | Cause | Fix |
|---|---|---|
| One Enter on a new row inserted the record twice | Enter saved; `setRowSaving` disabled the inputs, the focused one blurred and the row's `onBlur` saved again | `handleSaveRow` keeps a per-row in-flight set (`savingRowIdsRef`) |
| A business error (unique key, trigger) was POSTed 3 times; a network error after commit could insert twice | `saveRecordWithRetry` retried every `_general` error | Saves are sent once (`saveRecord`); the retry code was removed |
| A rejected new row disappeared with no message, the window stayed dirty | `rollbackOptimisticUpdate` dropped the new row while it stayed in `editingRows` | A failed new row stays on screen, still editable |
| Fast typing (barcode scanner) saved a truncated value (`"PW"` for `"PW fast typing"`) | `useThrottledCallback` ran the trailing call with the 2nd call's arguments and ignored the rest | Cell changes apply immediately (`useStableCallback` only keeps the identity) |
| Clicking a dropdown's search box on a new row saved the row | The row's `onBlur` used a DOM `contains` check; dropdowns and dialogs render in a portal | Focus moving into or out of a `menu`/`listbox`/`dialog` no longer counts as leaving the row |
| After a second save the grid showed the previous values; the next edit got a false stale-object 409 | The post-save `datasource.get` was answered from the 30 s response cache | The entity (and parent entity) cache is cleared first, as the form does |
| `"1,5"` became 15 in Spanish | `NumericCellEditor` stripped every comma | The user's language decimal separator is used, same rule as `NumericSelector` |
| Conversion errors (`status: -4`, `response.errors` map) showed "Unknown server error" | Only `response.error.message` was read | The map is joined into the message, as `useFormAction` does |
| The first save with validation errors showed no dialog | The dialog read the row snapshot taken before validating | It reads the row after validation |

## Pending parity gaps (not fixed)

Ranked by impact. File references are on `main` at the time of the audit.

1. **Extension-module fields**: the grid calls `buildSavePayload`, not `buildFormPayload`, so `em_*` values are not
   copied into the standard column (`utils/index.ts` `applyExtensionFieldMappings`). A window that shows only the
   module field fails on NOT NULL.
2. **Parent link on new child rows**: parent data is keyed by `inputName` (`useInlineEditInitialization.ts`), the save
   filter keeps only `hqlName`s; the link relies on the FIC, which fills it only for an AD_Field marked link-to-parent.
3. **New-row defaults are not post-processed**: no boolean conversion, static defaults or `@Column@` resolution
   (`useFormInitialState.ts` does them); `createEmptyRowData` keys defaults by label.
4. **Session context**: no SETSESSION reset before a root-tab NEW and FIC `sessionAttributes` are never merged, so
   callouts run with another record's context.
5. **Callouts**: no `waitForIdle` before saving (a save right after a product change misses price/tax/UOM); the
   changed value is sent unsanitized; `em_*` fields do not derive the standard `CHANGED_COLUMN`; selector out-fields
   only for `inpmProductId`.
6. **Display logic is not evaluated** (`displayLogicExpression: undefined`): hidden cells stay editable and hidden
   mandatory fields are still required.
7. **Optimistic snapshot**: insert/save/cancel copy every displayed row into `optimisticRecords`, which then hides
   newer base rows until an id disappears.
8. **Keyboard**: Escape is a document-wide listener in every mounted grid; the keyboard manager keeps mount-time
   closures; Tab order is alphabetical.
9. **After save**: no parent refresh (`triggerParentRefreshes`), no CSRF/AccessTableNoView logout handling.
10. **Shared with the form**: `accountingDate: new Date()` goes through `normalizeDates` and is sent as `{}`;
    `oldValues` is ignored by the server (only `data.updated` is checked, to the second).
