### `em_etmeta_payscript_logic` — `obuiapp_process`

```js
// @module-scope
// Mirrors the classic handler body (obwpl-movementline.js:37): confirm, one
// remote call, the server's message in the banner, then close to refresh the view.
const ACTION_HANDLER = "org.openbravo.warehouse.pickinglist.MovementLineHandler";
const CONFIRM_LABEL = "OBWPL_LineRejectConfirm";
const SERVER_ACTION = "reject";

const runMovementLineAction = async (recordIds) => {
  // Classic uses the bare isc.confirm(message, callback) form: no title override.
  if (!(await confirm(OB.I18N.getLabel(CONFIRM_LABEL)))) return { type: "closeModal" };

  const response = await callAction(ACTION_HANDLER, {
    movementlines: recordIds,
    action: SERVER_ACTION,
  });

  const message = response?.data?.message ?? {};
  return {
    message: { msgType: message.severity, msgTitle: message.title, msgText: message.text },
    responseActions: [{ refreshGrid: {} }],
  };
};

return { runMovementLineAction };
```

## Advisories (non-blocking)

1. **`closeProcessPopup()` made explicit.** The classic comment says the popup is closed *in order to*
   refresh the view — an implicit side effect. The migration states the intent directly with
   `refreshGrid`, which is more robust than relying on a close-triggered refetch.
2. **Loading prompt dropped** (`isc.showPrompt` / `isc.clearPrompt`): the modal already shows a pending
   state.
3. **Empty-selection guard added.** Classic would post an empty `movementlines` array; the migrated code
   returns an error message first. Deliberate, non-regressive deviation.
4. **`view.activeView` vs `view.view`.** The two clones in this file use `view.activeView.messageBar`
   while the SII family uses `view.view.messageBar`; both resolve to the same banner in the new UI, so
   the distinction disappears.

## Manual-test checklist

1. Open **Goods Movement** → the *Lines* tab, select one line, press **Reject**.
   → No empty dialog; the `OBWPL_LineRejectConfirm` confirmation appears immediately.
2. Press **Cancel**. → Dialog closes, no banner, no error, and the line's status is unchanged.
3. Repeat and press **OK**. → The server's message shows in the banner with its own severity, and the
   grid refreshes so the new line status is visible without reloading.
4. Select **several** lines and run it. → All ids go in a single call; every selected line changes state.
5. Force a server-side rejection (a line in a state the handler refuses). → Error banner; the modal
   stays open.
6. Run with **no** selection. → Error message instead of an empty call.
