## This is a special case: the custom-component rendering path

Almost every process in this report set renders the **standard metadata-driven parameter form** — a flat
list of fields built from `OBUIAPP_Parameter` rows. Create Packing does not, and cannot: its Classic UI
is a full packing station (box selector, barcode input, a live grid with one column per box) that has no
expression as a list of parameters. It has **zero `OBUIAPP_Parameter` rows**.

So it takes the path described in `new-ui-js-migration-guide` §9.1: `onLoad` returns a **schema** that
describes a bespoke UI, and the new UI renders `GenericWarehouseProcess` from that schema instead of the
parameter form.

**That path is opt-in, and the opt-in is a database flag, not code.**

```
EM_Etmeta_Custom_Component = 'Y'   →  onLoad's schema renders GenericWarehouseProcess
EM_Etmeta_Custom_Component = NULL  →  the schema is silently discarded; an empty dialog renders
```

The gate is `usesCustomComponent()`
(`Custom/GenericWarehouseProcess/customComponentUtils.ts:35-38`), which accepts `true` or `'Y'` only.
The flag is deliberately declarative: `useWarehousePlugin` will **not** speculatively run a process's
`onLoad` just to discover whether it returns a custom schema, because doing so would execute every
standard process's `onLoad` inside the reduced warehouse sandbox. So an unset flag is indistinguishable
from "this is an ordinary process", and the failure is silent.

### Why it did not render before

With the flag unset:

1. `useWarehousePlugin` short-circuits and never evaluates the schema-returning `onLoad`;
2. the **standard** `onLoad` path runs instead and hands the returned schema to
   `updateParametersFromOnLoadResult`, which does not know the key `type`, so it is dropped;
3. `renderParameters()` returns `null` (zero parameters), leaving an **empty dialog** with a live
   Execute button.

### Resolution

The flag was set manually through *Application Dictionary → Process Definition → Create Packing →
Custom Component* on **2026-08-19**, and the process was confirmed working against the live client.

```sql
-- Equivalent SQL, for reference. Verified state after the manual change:
-- em_etmeta_custom_component = 'Y', updated 2026-08-19 10:15.
UPDATE obuiapp_process
   SET em_etmeta_custom_component = 'Y'
 WHERE obuiapp_process_id = 'C4043A216BD7429BB4D77469E7886BAA';
```

No cache flush was required: the modal issues a live `POST meta/process/<id>` whenever the process has
zero parameters (`ProcessDefinitionModal.tsx:1278`), so the fresh flag arrives even when the cached
window metadata in `localStorage` is stale.

## Current code (verbatim from `etendodev`, unchanged by this migration)

### `em_etmeta_onload`

Signature `(_processDefinition, { selectedRecords })` — the **custom-component** signature. On this path
`useWarehousePlugin` invokes the script as
`executeStringFunction(onLoad, { callAction, fetchDatasource, OB, fetch: undefined }, processDefinition, { selectedRecords })`,
a **reduced context**: no `Metadata`, no `messageBar`, no `confirm`, no `callDatasource`, no
`BigDecimal`. This code only uses `callAction` and `OB.PropertyStore`, so it is consistent with that
sandbox.

```js
async (_processDefinition, { selectedRecords }) => {
  const recordId = selectedRecords?.[0]?.id;
  if (!recordId) throw new Error("No record selected");

  const showUOM = OB.PropertyStore.get("UomManagement") === "Y";
  const useOperativeQty = showUOM;
  const getOperativeQty = (line) => Number(line.operativeQty ?? line.operationQty) || 0;
  const getBaseQty = (line) => (useOperativeQty ? getOperativeQty(line) : Number(line.quantity) || 0);

  const response = await callAction("org.openbravo.warehouse.packing.action.ManagePackingAction", {
    processId: "83AD8A78FB1C4EDBB4A222A276498938",
    recordId,
    action: "open",
    _entityName: "obwpack_packingh",
  });

  const errorAction = response.responseActions?.find(
    (a) => a.showMsgInProcessView?.msgType === "error"
  );
  if (errorAction) throw new Error(errorAction.showMsgInProcessView?.msgText || "ManagePackingAction failed");

  const dataAction = response.responseActions?.find(
    (a) => a.returnData && Array.isArray(a.returnData.data)
  );
  if (!dataAction) throw new Error("No data returned from ManagePackingAction open");

  const resultData = dataAction.returnData;
  const gridData = resultData.data;
  const backendBoxNo = Number(resultData.boxNo) || 1;

  const lines = gridData.map((r) => {
    const boxColumns = {};
    for (let i = 1; i <= backendBoxNo; i++) {
      boxColumns["box" + i] = Number(r["box" + i] || 0);
    }
    const qtyVerified = Object.values(boxColumns).reduce((sum, v) => sum + v, 0);
    return {
      ...r,
      ...boxColumns,
      storageBin: r.storageBin || r.storageBinName || "",
      quantity: Number(r.quantity || 0),
      operationQty: getOperativeQty(r),
      qtyPending: Number(r.qtyPending ?? getBaseQty(r)),
      qtyVerified,
      boxed: Number(r.boxed || qtyVerified),
      productId: String(r.productId || ""),
      shipmentLineId: String(r.shipmentLineId || ""),
    };
  });

  return {
    type: "warehouseProcess",
    titleKey: "packing.title",
    recordId,
    inputBar: ["boxSelector", "addBox", "qty", "barcode", "checkCalculate"],
    gridColumns: [
      { field: "barcode",           labelKey: "packing.barcode",           align: "left"  },
      { field: "product",           labelKey: "packing.product",           align: "left"  },
      { field: "attributeSetValue", labelKey: "packing.attributeSetValue", align: "left"  },
      { field: "storageBin",        labelKey: "packing.storageBin",        align: "left"  },
      { field: "auom",              labelKey: "packing.auom",              align: "left"  },
      ...(showUOM
        ? [{ field: "operationQty",  labelKey: "packing.operativeQty",      align: "right" }]
        : [{ field: "quantity",      labelKey: "packing.qty",               align: "right" }]),
      { field: "qtyPending",        labelKey: "packing.qtyPending",        align: "right" },
    ],
    features: {
      dynamicBoxes: true,
      calculateWeight: true,
      trackScannedInputs: false,
      useOperativeQty,
    },
    initialData: {
      lines,
      boxCount: backendBoxNo,
      windowId: String(resultData.windowId || ""),
      valuecheck: Boolean(resultData.valuecheck),
    },
  };
}
```

The `type: "warehouseProcess"` discriminator is what `useWarehousePlugin` checks before accepting the
result as a schema; anything else is returned silently and the modal falls through to its normal render.

### `em_etmeta_payscript_logic`

A bare object literal, so `classifyPayscriptBody` sees `(` as the first significant character and routes
it to the **PayScript DSL** path (`moduleScope.ts:93`), where `registerPayScriptDSL` evaluates it and
registers it under the process id. `useWarehousePlugin` then picks it up via `getPayScriptRules` and
exposes it to the component. `onScan` is the one key the warehouse component reads.

```js
({
  onScan: async ({ barcode, qty, lines, callAction }) => {
    const showUOM = OB.PropertyStore.get("UomManagement") === "Y";
    const useOperativeQty = showUOM;
    const getOperativeQty = (line) => Number(line.operativeQty ?? line.operationQty) || 0;

    const validLines = (lines || [])
      .map((l) => {
        const lineId =
          l.shipmentLineId ||
          l.inOutLineId ||
          l.mInOutLineId ||
          l.lineId ||
          l.id ||
          null;

        if (!lineId) return null;

        const quantity = useOperativeQty ? getOperativeQty(l) : Number(l.quantity) || 0;
        let qtyVerified = 0;
        if (Number.isFinite(Number(l.boxed))) {
          qtyVerified = Number(l.boxed);
        } else if (Number.isFinite(Number(l.qtyPending))) {
          qtyVerified = quantity - Number(l.qtyPending);
        }

        return {
          lineId,
          shipmentLineId: lineId,
          attributeSetValueId: l.attributeSetValueId || null,
          productId: l.productId || null,
          quantity,
          qtyVerified,
        };
      })
      .filter(Boolean);

    const response = await callAction("org.openbravo.warehouse.packing.action.ValidateBarcodeAction", {
      processId: "71DEE8098CE74C939575FF57609952CC",
      barcode,
      productIds: (lines || []).map((l) => l.productId),
      validLines,
      strictMode: true,
      qty,
      entity: "MaterialMgmtShipmentInOutLine",
      _entityName: "obwpack_packingh",
    });

    const rd = response?.responseActions?.[0]?.returnData || {};
    const matchedLineId = rd?.matchedLineId || null;
    const conversionRate = rd?.qty;
    const productId = rd?.productId ?? null;

    if (matchedLineId && Number.isFinite(Number(conversionRate))) {
      return { matchField: "shipmentLineId", matchValue: matchedLineId, qty: Number(conversionRate) };
    }
    if (productId) {
      return { matchField: "productId", matchValue: productId, qty: Number(qty) };
    }
    return { error: true };
  },
})
```

### One timing note for QA

`isCustomComponent` is derived from the `processDefinition` **state**, which starts as the cached window
metadata and is replaced when the live `meta/process/<id>` response lands. If the cached copy lacks the
flag, the first render classifies the process as standard and only the second render mounts the
component. This is cosmetic (a possible flash of the empty dialog), not a correctness issue, but it is
the thing to watch if the dialog ever looks wrong for an instant on open.
